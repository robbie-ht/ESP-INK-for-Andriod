# 架构与协议边界

UI → EspInkController → EspInkClient → EspInkTransport → NativeBle → Android GATT。

图像与文字交互参考同级 `moink-R1.3.4/page/index.html`；设备连接、设置、图库与OTA遵循同级 `Moink-APP/docs/API.md` 和 `APP-INTEGRATION.md` 的B2协议。参考页面中的Wi-Fi HTTP接口不用于本应用。具体对应见 [页面功能对照](page-feature-map.md)。

## 创作与图像路径

当前源码版本为 **1.0.5+6**。照片导航采用A→B→C→A：`ComposerPage`只显示一个照片选择／结果区域和调整、发送按钮；点击照片区直接调用系统相册B；只有选图返回成功并读入照片后，UI才经`showCompositionEditor`打开调整页C。C默认开启墨水屏效果，可切回原图；裁切、文字、留白、滤镜以及拍立得／便签切换集中在C，主页不再并列这些参数。

正常选图由控制器`pickPhoto()`返回布尔结果，不在控制器持有导航上下文。UI流程锁覆盖等待B与整个C生命周期；取消或读取失败不改旧草稿、不打开C，异步返回后还核对页面是否仍存在、当前控制器和创作页是否匹配。C中的更换照片更新当前C，不压入第二个调整页；等待系统选图时，完成按钮和返回退出被锁定。

C的调整即时写入共享草稿，完成或系统返回都保留编辑。C关闭时停止自动预览订阅；A再显式请求一次当前版本效果，补齐退出前仍在240ms防抖窗口内的变更。最后一帧完成后A显示结果，后续不在隐藏页面持续量化；发送仍复用同一草稿版本的处理结果。“调整图片”直接打开C，不再次调用相册。裁切子页保持独立局部草稿，只有应用才提交，取消不回写。

`ComposerDraft` 只有拍立得和便签两种模式。`photoTexts`、`noteTexts` 保存各自的 `TextLayer` 列表，切换模式不混用文字。照片布局包含铺满/完整显示、缩放、平移、90°旋转、自由旋转、镜像和四边留白；文字包含位置、字号、旋转、换行宽度、字形、加粗、四色颜色/描边和可选底色。编辑与命中测试共用文字度量结果。

编辑空间采用正向横屏768×552。处理顺序是：

1. `PaperArtPainter(drawText:false)` 绘制照片和留白，或便签纯色底。
2. 仅照片的内容矩形进入 `image_filters.dart` 的 `warmMap` 和 `quantize`；白边不进入自动色阶、色调映射或抖动。便签和未选图状态跳过图片滤镜。
3. 将已量化的底图转换为纯黑、白、黄、红，再用 `PaperArtPainter(drawBase:false)` 叠加文字。
4. 最终合成图按最近调色板色吸附，不对文字边缘扩散误差。由同一份最终颜色码同时生成正向预览PNG和发送帧。
5. `pack2bpp` 独自执行180°旋转，并按每字节4像素、最高两位在先打包，固定得到105984字节。回读预览通过 `unpack2bpp` 恢复正向坐标。

参考页面使用竖向552×768编辑空间；本应用没有直接移用其额外90°编辑旋转，也不把已经旋转的传输缓冲当预览。用户选择的图像旋转与协议打包旋转是两个独立步骤。

`image_filters.dart` 是不依赖Flutter的纯Dart实现，包含4种风格、8种抖动、3种色域和原页面高级参数。误差扩散逐行蛇形扫描；标准档采用参考算法的γ=1.75及黄(255,230,0)/红(230,0,0)目标色。最终设备颜色码仍为0黑、1白、2黄、3红。`gray` 先转灰阶后继续四色量化，并非强制二色输出。

`test/image_filter_vectors.json` 由参考页面原始JS函数直接执行生成，并记录源文件SHA256。112组金标覆盖4风格×8抖动×3色域及高级参数/四套暖色渐变。该测试确认算法输出兼容，不代表不同照片解码器、字体排版引擎或实物墨水屏具有完全相同的视觉结果。

控制器用草稿版本号串行处理预览请求，合并连续编辑并丢弃过期渲染。发送前完成当前预览；发送使用帧快照，后续编辑不能改变正在上传的字节。

## 连接

仅Android提供真实BLE。原生层按UUID发现，串行执行连接/服务发现/EVT订阅/CCCD/MTU；完成后协议层才PING和读取状态。设备名仅用于显示。未协商到支持状态查询的MTU会明确失败，不将请求值517当实际值。

Android整个特征值最多512字节，DATA还有2字节片号，因此BEGIN请求为 `min(MTU-5,510)`。仍接受设备报告maximum512，但设备选择的实际chunk不能超过请求值；Dart与Kotlin的整包写入同时检查 `min(MTU-3,512)`。依据为 [AOSP BluetoothGatt](https://android.googlesource.com/platform/packages/modules/Bluetooth/+/refs/heads/main/framework/java/android/bluetooth/BluetoothGatt.java) 的属性值限制。不能把长包在桥中另行拆片，否则会破坏B2的片号与CRC契约。

原生GATT写完成只确认本地传输层，不能确认完整帧、持久化或显示。CTRL的业务回执在EVT；DATA完整性由END和GAP检测。所有修改作业串行化，完成事件监听在触发命令前登记。完成事件没有作业ID，结果超时或断连后标为待确认并阻止同连接继续修改，避免晚到事件污染新作业。

## 作业与错误

接收阶段 → END校验/受理阶段 → 已排队 → STORE_DONE / DISPLAY_DONE。只有接收阶段允许ABORT。排队后关闭弹层或断线不能称作取消；即便重连idle也无法补查丢失的上一作业结果。

立即显示、存入图库并显示、仅存入图库是独立的发送选择。追加并显示时，保存与显示分别保留结果；不能因DISPLAY失败便自动再次追加。超时副作用命令不重发。CTRL已超时或写入失败的seq退休至重连，避免回绕后误匹配迟到RSP；耗尽时要求重连。DATA采用实际chunk、精确末片、最多65536片、有限恢复；图像CRC可在原会话从0重传，OTA验证失败须重新BEGIN。

图库快照与下载核对revision、偏移、尺寸、格式、总长度和CRC；解码使用本次下载对应的元数据，STALE时丢弃部分数据。图库容量由设备报告，满时由用户删图，不自动覆盖。连接断开或切换设备清空本地设备图库缓存，slot/revision相同也不沿用另一个设备的图片。

## 设置与OTA

设置只发送变动字段；本地校验整组TLV、UTF-8 20字节名称和GPIO规则，再单包写入。超MTU不拆分事务。成功后回读设置；引脚改变需要重启，读取的是目标配置，不代表硬件已应用。

当前固件无已保存设置、恢复出厂或非法预设回落时采用整合板 `gpio_preset=2`，引脚按 `[ADC,WAKE,SCK,MOSI,CS,DC,RST,BUSY]` 为 `[0,1,4,3,5,6,7,10]`。GPIO2固定用于自锁，不可分配给上述功能。已有有效NVS配置保留；切换整合板应只设置preset2，重启并回读核对。屏型出厂仍为A0，GPIO预设不决定屏型。

固件仅接受ESP32-C3应用镜像，检查E9、chip_id=5、1024..0x160000以及片数。OTA_END成功只确认设备校验/选择启动槽，版本与新镜像45秒确认仍需重连与真机检查；普通BLE断开不能证明升级成功。首次R/B1→B2分区迁移使用USB完整刷入，不能经此BLE OTA完成。旧页面的HTML更新和热点设置不属于B2应用接口。

## 数据与隐私

草稿文字、两种模式的布局和图像参数以 `composer.v2` 保存于本地SharedPreferences。照片字节不写入草稿，普通重新启动后需重新选图。Android照片选择器中断恢复与正常选图共用空文件／24MiB检查和几何重置；恢复请求只消费一次，并在创作页可导航时进入C。选图代次防止迟到恢复覆盖后发起的普通选择，正常新照片也会清除未消费的旧恢复请求。图像处理在本地完成，不上传云端。黑体、宋体、等宽字体随应用打包，无远程字体请求。

诊断日志仅内存保留最近200条，可复制。应用不建立账号，不接入统计或远程服务；debug安装签名不是发行身份。

本地演示使用独立标志，connected仍为false，示例图库由便签生成。演示完成文案明确“未发送到设备”。浏览器只提供创作、界面与本地演示；Android真机能力在页面内区分。各项验证证据与构建结果统一记录在 [VERIFICATION.md](VERIFICATION.md)。

展开区域与各设置弹层使用独立 `PageStorageKey`。展开控件的布尔状态不能与祖先滚动区的数值offset共用键；否则切换页面恢复状态时会类型错误。回归覆盖滚动设备页、来回切页和恢复展开状态。

## 1.0.3 自动效果、后台读取与采样状态

效果模式和独立效果调整页激活自动处理：首帧立即、后续240ms防抖；处理共用单队列并按版本合并，新版本迟到结果不发布。调整同一张照片时保留最近有效效果并显示更新中；换图清除旧效果。离开创作、切回原图或应用进入后台停止排队；已在处理的结果可以缓存，但不改变用户当前模式。发送仍使用同一草稿快照的帧、PNG和标题。

效果页竖屏采用固定上方预览、下方独立滚动参数；横屏采用左右分栏。页面与主画面共享控制器状态，使用gapless图像更新及稳定的预览容器键，避免参数变更、按钮插入导致图片重新解码和闪空。弹层关闭后恢复此前的模式。

图库进入后先串行读缩略图，600ms空闲窗口后补读完整帧；只在前台、图库页、设备idle、没有前台作业和状态读取时发起。离页、后台、用户前台读取和修改作业取消后续片段，但必须先等待已发出的当前响应排空。读操作不发ABORT，也不产生修改结果待确认。完整帧失败每个身份只尝试一次，设备BUSY则在后续idle状态确认后允许重试，避免忙等。打开的大图会接收同身份后台高清更新，保留用户当前缩放。

revision整体改变通常应清理缓存；确认是当前连接刚完成的一次追加时除外。追加证据同时要求STORE_DONE保存成功、slot/count正确、旧元数据前缀逐项一致且revision只前进一步（0xffffffff回到1）。由此迁移已验证完整帧的身份；保存成功但显示失败同样保留。删除、清空、换槽、异常revision或断线不能套用此例外，CRC16不足以单独证明身份。缓存仍为当前会话内存，不承诺退出APP或重连后持久保存。

GET_STATUS中的非正bat_mv表示本次无有效采样，不能据此推断没电。当前连接保留上次真实正值，标注旧读数和采样时间；新正值及低电量事件更新数值，断线和演示清除。每15秒空闲轻量GET_STATUS，不读取全套设置或图库；应用后台、正在操作、已断开时不发起轮询。已在途请求仍按协议队列完成或超时。


## 1.0.4 ESP-INK品牌与应用身份

应用显示名称统一ESP-INK，Dart包esp_ink，Android包io.github.robbieht.espink；Kotlin包与三组平台通道同名迁移，BLE服务/特征UUID和报文字节保持不变。这里的新包名独立安装是指相对旧MoInk 1.0.3及更早版本，不覆盖或自动继承该旧应用的草稿／权限；原相册文件不删除，新图片保存到Pictures/ESP-INK。ESP-INK 1.0.5沿用1.0.4应用ID，相同签名的安装包可覆盖更新，未再次更改安装身份。历史协议/构建证据及参考项目原名保留用于来源追溯。
