# 刷屏期间读取图库

本功能需 ESP-INK APP 1.0.7+8 与支持只读窗口的 ESP_INK B2.0.1 固件配合。旧B2.0.0仍能使用新APP，但读取新高清会等刷屏完成；已缓存预览可直接查看。

固件基线为 [ESP_INK / 4909e4c](https://github.com/robbie-ht/ESP_INK/tree/4909e4c36172daa1d54a21ae4d4f0d6998eac007)。原版非IDLE统一拒绝图库INFO/LIST/READ，而APP也把读取排在整个显示作业后。

## 固件窗口

仍使用api=1、原状态3/4及原分区。GET_STATUS在版本字符串后追加可选一字节flags；STATE事件保留原arg状态，追加同样flags。bit0代表支持，bit1代表当前安全物理刷新窗口，bit2代表本窗口开始前该帧已成功追加图库。旧客户端可忽略尾字段；新客户端缺字段时继续串行，不按版本字符串猜能力。

仅在图库保存/载入或缓存载入完成后开启窗口，执行epd和面板deep_sleep后，先关闭窗口，再更新current、NVS和缓存。关闭取得与BLE命令相同的互斥锁，先排空已经进入的分片读取。窗口只允许图库INFO/LIST/READ，上传、删除、清空、设置、电源转换和OTA仍须IDLE。STORE_DONE和DISPLAY_DONE的原有末尾时序保留。单片图库数据最多496字节，整个通知值不超过512字节。

## APP队列和缓存

修改作业保持单队列；图库读使用独立串行队列。只有固件明确开窗，且本APP的当前作业已受理并仅在等显示（或是设备外部发起的刷新），读取才能并行。后来排队的修改会等已发读取排空。窗口关闭后停止下一分片，不向只读命令发送ABORT。旧状态回复不能覆盖后来收到的新STATE或DISPLAY_DONE。

读图只更新对应图库条目的进度，不能清掉前台刷屏的busy、提示或进度。后台读取只在图库页和APP前台执行；离页或进入后台停止后续分片。设备BUSY采用状态变化后重试，防止持续发送。CRC、完整元数据和图库revision校验保留。

存并显示时，只有本会话的已受理追加、固件bit2及完整列表验证能建立独立的窗口追加证据；不能把“正在刷新”当作保存成功。最终STORE_DONE仍需核对。无法确认身份的变化不沿用旧高清。

## 使用及验证边界

先安装对应APP，已采用B2分区表的设备可在APP固件升级中选择B2.0.1的app.bin。R系列/B1分区不兼容，不能直接使用该OTA文件迁移。无需为本次功能擦除图库或恢复设置。助手不连接、不刷写设备。

构建、自动回归和文件完整性结果见[验证记录](VERIFICATION.md)；真实BLE吞吐、屏幕与Flash并发仍需使用者在设备上检查[真机步骤](hardware-check.md)。模拟测试不能代替手机和面板验收。
